**统一设计原则**（六维共用）：

1. **旁路增强**：任何增强能力（规划/工具/记忆/经验）挂掉都必须退回基础链路，绝不阻塞上课；
2. **确定性优先**：规则永远先算，模型是增强项（计划、工具、蒸馏皆如此）；
3. **可单独关闭**：每个维度一个开关，全关即回到「单次生成 + 规则分流」的最小系统；
4. **失败可观测**：降级/回退/异常必须留痕（`AgentBus` 的 `fallback` / `error` 消息 + `turn.meta`）。

## 1. 角色设定（Role & Persona）

### 1.1 设计要点

* **角色 = 职责边界 + 协作协议 + 人格载体，三者分离**。职责写在代码里（谁负责什么），协议写在消息里（怎么交互），人格写在 Markdown 里（说话像谁）——改人格不该碰代码，改职责才碰代码；
* **职责用「负责 / 不负责」双向声明**。多个 Agent 能力重叠是事故之源，重叠处必须显式指定唯一所有者（如"答疑"归 `teacher`、"逐页讲解"归 `lecturer`）；
* **人格是声明式事实源，运行期现读**：一科一份 `SKILL.md`，改 md 即生效、无需改代码与重启；
* **提示词分层装配，层序 = 影响力序**（越靠后越强）：共享层保证同一角色跨链路口吻一致，任务层各自持有；
* **差异正交**：角色承载「怎么做」（契约），学科承载「像谁」（人格），老师承载「个人手感」（经验层）。

### 1.2 本项目落地

| 机制 | 位置与行为 |
|---|---|
| 角色声明 | `agents/protocol.py:50-54` 字符串常量（`ROLE_SUPERVISOR / ROLE_ROUTER / ROLE_TEACHER / ROLE_LECTURER / ROLE_STUDENT`）；`BaseAgent` 只提供 `role` + 生命周期钩子（`agents/base.py`） |
| 职责表 | `agents/__init__.py` 的角色→实现类映射 + `agents/<角色>/nodes.py` 的 `NodeSpec`（名称/摘要/输入输出/依赖/实现） |
| 交互协议 | `AgentMessage(sender/recipient/kind/detail/ok/payload)`，`kind ∈ {request, response, handoff, fallback, error}`；`AgentBus` 全 `classmethod` 无状态，扇出客户端事件 `agent_message` 并写 `session.scratch["agent_trace"]` 环形缓冲（上限 80 条） |
| 人格事实源 | `.agents/skills/<学科>/SKILL.md` frontmatter：`persona / tone / depth / speech_rate / teaching_style / catchphrases / do / dont` 等，经 `core/skills/teacher_personality/md_teacher.py` 适配 |
| 提示词装配 | `agents/shared/teaching_layers.py:269-318` `build_messages()`：身份基座 → 任务契约 → 学科约束 → hint → extra_system → 共享人格层（讲课风格 → 老师人格 → 全局规则 + 学科人格 → **学情记忆** → 教师经验）→ 覆盖层 → 历史 → 本轮 user |
| 防串台 | 人格的 `subject_id` 与当前学科不一致即丢弃（`build_profile_layers`，`teaching_layers.py:179-266`）；任一层异常只告警不中断 |

### 1.3 检查清单

- [ ] 每个角色有明确的「负责 / 不负责」清单，无未指定归属的交叉能力
- [ ] 人格/风格可热改（改文件即生效），不需重新部署
- [ ] 提示词分层有书面层序说明，且「覆盖层」能压过人格层（避免人格与任务打架）
- [ ] 跨角色交互 100% 有追踪记录，且追踪失败不影响主链路
- [ ] 同一角色在不同链路上口吻一致（共享层复用，非各自复制）

### 1.4 差距

* `TeacherAgent` / `StudentAgent` 的 `role` 用字面量而非 `protocol.py` 常量，存在拼写漂移风险；
* `agents/shared/teaching_layers.py` 的层序只在代码注释里，缺一份可视化「层序图」；
* 角色能力边界靠文档约定，尚无自动化一致性测试（如断言「lecturer 不写正文板书」）。

## 2. 任务分解（Planning）

### 2.1 设计要点

* **先确定性、后模型**：规则计划永远先算；LLM 计划是增量增强，任何失败（超时/异常/无 key）静默回退；
* **计划是数据结构，不是自然语言**：frozen dataclass + 封闭词表，模型输出必须被归一化（未知动作归 `explain`、白名单外工具直接丢弃），防止幻觉出的能力被当真；
* **计划要回注上下文**：把「执行计划」文本拼进本轮 user，模型才知道自己在执行什么、避免答偏；
* **子任务不重复规划**：多意图拆出的子回合复用规则计划，控制模型开销；
* **编排双轨同源**：内建编排与图编排（LangGraph）必须复用同一批节点实现，避免两套代码分叉。

### 2.2 本项目落地

| 机制 | 位置与行为 |
|---|---|
| 计划模型 | `core/planning/planner.py:87-126` `TurnPlan(goal, steps[PlanStep(action, detail)], tools, ask_followup, source, reason)`，frozen dataclass，`to_meta()` / `notes()` |
| 词表约束 | `ACTIONS = (clarify, retrieve, explain, verify, ask_followup)`；`TOOLS = (knowledge_search, math_solve, math_verify, ocr_parse, read_board)`；goal ≤40 字、steps ≤5 |
| 两级生成 | `planner.py:155-187`：规则计划兜底 → `AGENT_PLANNER_ENABLE` 且非 Mock → `wait_for(llm.chat_json, 6s)` → `_from_llm` 归一化 → 失败回退 |
| 调用点 | `agents/supervisor/agent.py:622-644` `_resolve_plan()`（按 `turn.meta` 缓存，流式与非流式共用一份）；`_plan_notes()`（:646）产出注入文本 |
| 图编排 | `core/graph.py` 自研 `TaskGraph`（拓扑序 + `__skip__/__stop__` 分支）；`core/turn_graph.py` 回合主图（`route/control/chitchat/teach/answer_check/multi_intent`）；`core/langgraph_flow.py` 答疑子图；节点复用 Supervisor 的 `_turn_*` 方法 |
| 开关 | `config/settings.py:67-76`（`agent_planner_enable=True`、超时 6.0s、max_tokens 400）；`:132` `orchestrator`（默认 `builtin`） |

### 2.3 检查清单

- [ ] 计划字段有封闭词表，模型输出经归一化才可使用
- [ ] 规划超时 ≤ 单次交互可接受停顿（当前 6s），超时后首响不受影响
- [ ] 计划文本回注上下文，且可被关闭（`AGENT_PLANNER_ENABLE=false` 时链路行为可预测）
- [ ] 多意图/单意图/复杂三种形态都有规则兜底分支
- [ ] 图编排与内建编排的节点实现同源，有测试保证等价

### 2.4 差距

* 计划目前只覆盖「答疑回合」，课件讲解链路未走 planner；
* `PlanStep` 无执行结果回填（计划与执行的一致性无校验，属 P2 可观测项）；
* 计划质量无离线评估集（建议补：同一问题在 planner 开/关下的首响与正确率对照）。

## 3. 工具调用（Tool Calling）

### 3.1 设计要点

* **工具集最小化 + 白名单注册**：模型只能调用「已注册且在本回合白名单内」的工具，未注册即不可达；
* **能力分工明确**：模型给「内容」，系统给「版式」——坐标级写作工具刻意不暴露给模型；
* **失败也是观察**：工具异常不向上抛，转成 observation 文本回灌模型（参数错/工具名错/额度耗尽/执行异常四类可区分）；
* **额度与超时双闸**：单回合调用次数上限 + 整环超时，且只对「整环」计时（不做无谓的单工具计时）；
* **收尾保证产出**：ReAct 步数用尽必须强制一次 `tool_choice="none"` 的 JSON 收尾，绝不能空手而归；
* **可观测**：每次调用记录（工具名/参数/观察/耗时/成败/原因）并入 `turn.meta` 与 AgentBus。

### 3.2 本项目落地

| 机制 | 位置与行为 |
|---|---|
| 工具运行时 | `agents/shared/toolkit.py` `AgentToolkit(session, parser, retriever, board, max_calls)`：内部复用 `mcp_tools/registry.py` 的注册表，再用 `_handlers` 建运行时白名单 |
| 六个工具 | `knowledge_search`（知识检索）· `math_solve`（sympy 求解）· `math_verify`（复核）· `ocr_parse`（取会话内已 OCR 题干，不传二进制）· `read_board`（读白板，≤12 行）· `whiteboard_note`（追加一行补充） |
| 刻意不暴露 | 坐标级 `whiteboard_write` / `whiteboard_clear` 只对 MCP 外部开放，版式由确定性布局器 `Whiteboard` 负责 |
| 调用护栏 | `AgentToolkit.call()` 唯一执行口：`bad_arguments / unknown_tool / limit / exception` 全部转观察文本，观察截断 600 字，默认额度 `agent_tool_max_calls=6` |
| ReAct 闭环 | `agents/teacher/react.py`：`for index in range(max_steps=4)` → 第 1 轮 `tool_choice="auto"` 不强制 JSON；模型不再要工具即 `STOP_ANSWER`；步数用尽补一次 `tool_choice="none"` + JSON 收尾；整环 `wait_for(45s)`；不支持工具/超时/异常 → **空文本 + 结束原因**，由调用方回退单次生成 |
| 降级开关 | `AGENT_TOOLS_ENABLE` / `AGENT_REACT_ENABLE` 任一关闭 → 回到确定性流水线；ReAct 开启时答疑不走并行流式话术（先复核再讲，牺牲数秒首响） |

### 3.3 检查清单

- [ ] 工具有唯一注册中心，且模型可见清单 = 白名单（非默认全量）
- [ ] 高危/越权能力（写坐标、删数据、外网请求）默认不暴露
- [ ] 工具失败 100% 转观察文本，链路不因工具异常中断
- [ ] 有次数上限、超时上限、观察长度上限
- [ ] 每回合有工具调用轨迹（可回放、可统计调用率/失败率）
- [ ] 工具效果可对照（开/关 ReAct 的首响、正确率、工具命中率）

### 3.4 差距

* 无声明式 ACL 与单工具超时（当前靠白名单 + 整环超时）；
* 工具选择质量无离线集（哪些问题该调哪个工具、是否答非所问，无评测）；
* `mcp_tools` 对外暴露 `whiteboard_write` 等坐标能力，缺少对外调用的鉴权说明（见 `deploy/` 与 `anti_rev.py` 现状）。

## 4. 记忆与上下文（Memory & Context）

### 4.1 设计要点

* **记忆分层且正交**：会话内历史（短时）→ 学生学情记忆（长期，按学生）→ 教师经验（长期，按老师）；三者不同源、不同权、物理隔离；
* **按主体隔离**：经验回答「老师怎么讲更有效」，记忆回答「这位学生哪儿不会」；**绝不跨学生复用记忆**；
* **写读解耦**：写入分「零成本即时写」（判题答错）与「异步蒸馏写」（可关，省额度）；读取做相关性检索 + 条数上限；
* **注入位置有讲究**：层序 = 影响力，记忆放在人格之后、经验之前（人格 > 记忆 > 经验）；
* **合规可回溯**：append-only + 相似度去重（≥0.85 累加 hits）+ 支持停用/恢复/**物理删除**；
* **旁路增强**：记忆读写、蒸馏、经验反思的任何异常都只记日志，绝不阻塞课堂；
* **上下文裁剪显式化**：窗口大小按链路配置（答疑 6 条、讲解 0 条），不做隐式截断。

### 4.2 本项目落地

| 机制 | 位置与行为 |
|---|---|
| 学情存储 | `core/memory/store.py`：`data/memory/students/<student_id>.jsonl`，append-only 按 id 折叠；相似度 ≥0.85 判重；`active(subject)` 过滤；`search = item.score + bigram Jaccard × 2.0`；`retire/restore/forget`（`forget` 物理删除，合规） |
| 读路径 | `core/memory/prompt.py::build_memory_prompt_for(session)`：取 `student_id` + 最近学生问题（前 120 字）为 query，`memory_inject_limit=5`；异常/关闭返回空串；注入点 `teaching_layers.py:243-251` |
| 写路径 | 即时：`Supervisor._record_mistake_memory()`（判题首次答错，零 LLM 成本）；异步：`_schedule_memory_distill()`（`MEMORY_DISTILL_ENABLE` 默认关，节流 120s，最多 2 条/次，8s 超时） |
| 教师经验 | `core/skills/experience/`：`data/teacher_experience/<老师>.jsonl`；`SkillReflector.reflect()` 只提炼「换题换人仍成立」的通用经验，空手而归允许；相似度去重 + 置信度门槛 + 条数上限；`retire/restore` 即回滚；调度入口 `Supervisor._schedule_skill_reflection()`（fire-and-forget） |
| 会话上下文 | `core/state/session.py` `SessionState`：`history / scratch / board_seq / board_ops / board_images / pending_question / speech_epoch / deck_id / page_index / quiz` 等；`build_messages(history_limit=6)`，讲解链路传 0 实现链路隔离 |
| 开关 | `MEMORY_ENABLE=True`、`MEMORY_INJECT_LIMIT=5`、`MEMORY_MAX_ITEMS=0`（不限）、`MEMORY_DISTILL_ENABLE=False`、`SKILL_SELF_UPDATE_ENABLE=True`、`SKILL_EXPERIENCE_INJECT_LIMIT=6` |

### 4.3 检查清单

- [ ] 记忆按主体隔离（学生/老师各自存储，无交叉读取路径）
- [ ] 有删除能力且是真删除（含缓存失效）
- [ ] 注入有条数上限与相关性排序，不整份灌入
- [ ] 读写路径都有开关，关闭后链路行为不变
- [ ] 记忆不影响人格（记忆永远不能改写 `.agents/skills/**`）
- [ ] 上下文窗口按链路显式配置并写入文档

### 4.4 差距

* 检索为 bigram 轻量实现（记忆与教材同此），数据量增大后建议迁移向量库；
* 无记忆「过期/衰减」策略（`MAX_ITEMS=0` 不限，长期只增不降权）；
* 会话上下文无摘要压缩（长会话只靠 `history_limit` 截断，早期有效信息会丢）；
* 断线续聊的**回读**未接线（见 §5.4）。

## 5. 多轮对话（Multi-turn）

### 5.1 设计要点

* **回合 = 一次事件**：客户端事件白名单分发，未知事件静默忽略；串行处理 + 超时帧（保证定时任务与长任务不互相饿死）；
* **追问状态机化**：pending 结构显式维护（问题/期望/提示/选项/已试次数），追问次数有上限，且「追问回合」与「新提问回合」互斥；
* **意图判定要保守**：选项精确命中才算作答；含疑问特征、超长文本、带句读一律按新提问处理（宁可重新讲解，不可误判作答）；
* **打断即让位**：学生输入先自增 `speech_epoch`（每次输入只计一次），长链路（连讲）在下一个安全边界收工，不由打断方强制杀进程；
* **现场可恢复**：关键状态定期快照（白板 + 历史 + 页序），为断线续聊留口。

### 5.2 本项目落地

| 机制 | 位置与行为 |
|---|---|
| 事件分发 | `core/loop.py::_dispatch()`：`text / voice / image / interrupt / vad / ping / idle / course_* / slide_* / quiz_request` 等白名单；图片超限直接回话术；`run()` 用 0.5s 超时帧跑 `_course_quiz_tick()` |
| 队列与抢占 | `submit()`：`slide_ready` 就地处理不入队（避免连讲卡队列）；`text/voice/image/interrupt/courseware/slide_*` 入队瞬间 `_barge_in()`（`loop.py:120`：`speech_epoch += 1` + `avatar_interrupt`） |
| 追问闭环 | `Supervisor._ask_followup()`：`interaction_enable` 且 `followup_asked < interaction_max_followups(1)`；写 `pending_question{question, expected, hint, options, attempts, source_title}` + `push_event("ai_ask")` |
| 作答判定 | `_should_treat_as_answer(turn)`：pending 空/图片/控制指令 → 否；选项精确命中 → 是；含疑问特征或 >30 字或含句读 → 新提问；作答走 `_turn_answer_check()`（`build_judge_graph`：evaluate → decide → announce） |
| 回合互斥 | 新一轮答疑 `_turn_teach()` 清空 `pending_question` 与 `followup_asked` |
| 断线快照 | `core/checkpoint.py`：`data/raw/checkpoints/<session_id>.json`（board_ops[-500:]、history[-200:]，**不含** scratch/pending/epoch）；`server/websocket.py:160` 断开时 `harness.checkpoint(state)` 保存 |
| 轮次标识 | `speech_epoch` 同时用于连讲交接去重（`_record_lecture_handoff`，多意图每轮只记一次）与页等待中断（`_await_page_played(index, epoch=...)`） |

### 5.3 检查清单

- [ ] 事件类型白名单 + 未知事件静默忽略，前端加新事件不炸后端
- [ ] 追问有状态、有次数上限、有超时退出（不会无限等）
- [ ] 「追问作答」与「新提问」判定规则明确且保守（可单测）
- [ ] 打断只标轮次（epoch 单次自增），长链路在边界收工，无强杀
- [ ] 断线快照有落盘、有长度上限、有加载入口（可回灌）
- [ ] 多轮上下文有窗口策略，且各链路（答疑/讲解）隔离

### 5.4 差距

* **检查点「只写未读」**：`Checkpointer.load()` 全仓库无调用方，重连回灌未接线（快照已落盘，接入点建议放 WS 重连握手处）；
* 快照不含 `pending_question` / `speech_epoch`，重连后追问状态无法恢复（需扩展 payload）；
* 会话状态存内存（`SessionStore`），多实例部署需切 Redis（见 `待补齐规划.md` P2）；
* 语音链路仍是「音频片段 → 整段 ASR」，非流式（同上 P0）。

## 6. 拒答兜底（Refusal & Fallback）

### 6.1 设计要点

* **分层防御，各管一段**：入口护栏（该不该答）→ 生成契约（答得是否合规）→ 输出校验（有没有答坏）→ 链路降级（答不出来怎么办）；
* **拒答要礼貌且给出口**：拒答话术必须解释「为什么」并给替代路径（回到本课范围），不冷冰冰；
* **永远不哑巴**：任何链路失败都必须有可出口的话术（讲课失败念要点、答疑失败给引导话术）；
* **定点修复优于整体丢弃**：非法白板指令只丢非法项，不清空整块（历史 bug 的教训）；
* **降级要留痕**：fallback / error 必须落 AgentBus 与 `turn.meta`，可统计、可告警；
* **拒答有边界意识**：学科范围、内容安全、作业代写、超纲内容四类要有明确策略（当前只落地了第一类）。

### 6.2 本项目落地

| 层次 | 位置与行为 |
|---|---|
| 入口护栏 | `core/guardrail.py::screen_subject()`（`guardrail.py:65`）：学科已选且明确指向其它学科 → `in_scope=False` + `redirect_speech`；接线点唯一：`Supervisor._turn_teach()`（`agent.py:406-411`）判否直接播报拒答话术、不进答疑链路 |
| 生成契约 | `agents/teacher/agent.py::compose_answer()` 四层：正常解析 → `salvage_object()` 就地抢救 → `_repair_json()` 让模型重发 → `_compose_response()` 兜底（抢救到 speech 就用，否则固定引导话术） |
| 输出校验 | `core/validator.py`：`empty_response / speech_too_long(>800) / speech_not_chinese / sensitive:{pat} / answer_leaked`（提示级别下禁止直接给答案）/ 白板坐标越界；`drop_invalid_board_ops()` 定点丢弃非法指令；调用点 `langgraph_flow.py` 的 `validate → degrade` 节点与 `_finalize_streamed_response()` |
| 讲课降级链 | `agents/lecturer/nodes.py`：`request → explain → fallback → degrade`；fallback 回退 `TeacherAgent.explain_slide` 记 `KIND_FALLBACK`；再失败记 `KIND_ERROR` 并输出 `DEGRADED_SPEECH`（"这一页的内容我们待会儿再看，先接着往下讲。"）——绝不哑巴翻页 |
| 答疑最终兜底 | `Supervisor` 侧 `AIResponse(speech="这道题我们再想想看。")`；闲聊固定话术；多意图全空固定话术；OCR 无结果提示重拍；图片超限提示换小图 |
| 韧性工具（未接线） | `core/resilience.py`：`CircuitBreaker(5, 20s)` / `with_timeout` / `async_retry(3, 0.2)` / `first_success`——能力已实现，当前无调用方，实际降级靠各链路就地 try/except |
| 开关 | `guardrail_enable=True`、`content_safety_enable=True`、`ai_content_watermark_enable=True`；`filter_output()` / `tag_ai_content()` / `screen_question()` 已实现但**未接入主链路** |

### 6.3 检查清单

- [ ] 拒答策略覆盖：学科越界 / 内容安全 / 作业代写 / 超纲 / 无法回答，各有话术与判定
- [ ] 每条链路（答疑/讲课/语音/图片）都有明确的最终兜底话术，且经过测试
- [ ] 输出校验不通过时的处理是「定点修复」而非「整块丢弃/整句拦截」
- [ ] 护栏与校验均有开关，关闭后行为可预测
- [ ] 降级/回退/拒答全部可统计（次数、原因、链路）
- [ ] AI 生成内容有标识/水印能力且已接线

### 6.4 差距

* `filter_output()`（敏感词遮蔽）与 `screen_question()`（超纲拦截）已实现但无调用方，内容安全过滤实际未生效；
* `resilience.py` 的重试/熔断/降级未接入 LLM/ASR/TTS 调用点，真实抖动下缺少统一保护；
* 「作业代写」类拒答无独立策略（当前靠提示词约束，无代码兜底）；
* 拒答/兜底话术散落在各文件常量中，无统一话术表（建议集中为 `guardrail` 侧配置，便于运营调整与多语言）。
