## 八、迁移步骤（新机 Checklist）

1. **选镜像**：PyTorch + CUDA 预装镜像（AutoDL/优云智算任选），开机先 `bash deploy/cloud/check_gpu.sh`；
2. **同步代码**：`python scripts/sync_cloud.py`（需先改新机连接信息，见第九节）或直接 `git clone`；

5. **模型权重**：`bash deploy/cloud/download_models.sh`，或从旧机 `rsync` `models_zoo/`（16G）；
6. **素材与配置**：拷 `data/teachers/`、`data/teacher_voice/`、`.env`、`education.db`；
7. **一键启动**：`bash deploy/cloud/start_all.sh`；
8. **验证**：
   ```bash
   curl http://127.0.0.1:8001/health     # 主应用
   ```

## 十、已知坑（迁移必读）

1. **CosyVoice 必须 conda `cv310`（Python 3.10 + torch 2.3.1+cu121）**：用 py3.12 venv 会 dtype/conv 报错甚至请求永久挂起（表现为「老师不出声」）；
2. **MuseTalk 实际跑在 `.venvs/musetalk`（py3.12 + torch 2.8）**：`start_all.sh` 会优先探 conda `mt310`（本机不存在会自动回退 venv），以进程实测为准；
3. **AutoDL 的 `python3` 可能不在 PATH**（在 `/root/miniconda3/bin`）：`start_all.sh` 会自动补；
4. **实例重启后**：SSH 端口/密码、cpolar 域名都会变；旧进程占端口时用 `restart_app.sh` / `restart_tts.sh`（扫 `/proc` 精确匹配），**不要用 pkill**；
5. **显存红线**：全栈常驻 17.2G；若再启「本地 AWQ 大脑（≈7-8G）」24G 卡即 OOM，需 48G 卡或保持在线大脑；
6. **V100(sm_70) 老架构**：vLLM 需 `VLLM_ATTENTION_BACKEND=XFORMERS`（脚本自动检测）；4090 无此问题；
7. **合规开关**：面向未成年人，`GUARDRAIL_ENABLE` / `CONTENT_SAFETY_ENABLE` / `AI_CONTENT_WATERMARK_ENABLE` 迁移后保持 `true`；生产改强 `ANTI_REV_SECRET`。
8. **免费隧道会静默失效**：cpolar 进程可能消失而日志仍留旧域名（实测 10-09 停到 10-12）；判断公网可用性必须实测 `curl <域名>/health`，恢复用 `bash deploy/cloud/resume.sh`（走 cloudflared，幂等），最新链接看 `deploy/cloud/logs/public_url.txt`。
10. **讲课口型质量：底片循环范围已限定**（2026-10-12）：MuseTalk 从「底片闭嘴」的帧生成「大张口型」时容易豁口/摊平（实测 chinese_logic 的 **f82~f136** 段最差——底片这 2 秒在闭嘴，10 秒一轮循环到它时质量明显下降，表现为「刚开始好、讲到后面变差」）。解法：`MUSETALK_TALK_RANGE=192,240`（见 `_restart_engine.sh`）——把底片循环限定在「底片本身正在说话」的 2 秒段落，口型生成明显更稳、逐段特写全部自然。**代价**：动作库变短、画面循环周期从 10 秒缩到 2 秒；若觉得「老师动作重复」可放宽（如 `150,240`）后重启引擎。**换新底片素材时必须按新素材重新标定该范围**（方法：逐帧嘴开度曲线 + 分段渲染特写对比）。⚠ **2026-10-13 已按用户要求彻底回退**：`TALK_RANGE` 相关代码与参数已全部移除（恢复原始的全片循环）；如将来需要，按本节方法重新实现与标定。
9. **讲课嘴唇颜色已校准**（2026-10-12）：MuseTalk 重绘的下半脸比底片原色更红艳（实测饱和度 +10~25、绿通道低 7~25），导致「待机画面（底片原色）↔ 讲课画面（渲染）」切换时嘴唇颜色跳变。引擎已内置「嘴部色校准」：对嘴唇像素（生成区域内红度 top 4%）做 **Lab 三通道均值平移**（L 明暗 / a 红绿 / b 黄蓝 同时向底片同帧对齐），mask 羽化 + 幅度限制（±22）+ 异常跳过，绝不阻断渲染。⚠ **踩过的坑**：初版用「饱和度缩放 + 绿通道平移」双重去红会过冲——S/G 看似对齐，但 Lab a 偏低（偏绿）、亮度偏暗，嘴唇呈「灰白」；修算法后必须按「视觉 + Lab a/b/V 多指标」一起验收，不能只看饱和度。⚠ **2026-10-13 已按用户要求彻底回退**：嘴唇色校准与上唇边界相关的**代码已从引擎中移除**（`MOUTH_COLOR_FIX` / `_calibrate_mouth_color` / 启动参数覆盖），渲染行为与改动前完全一致；预处理缓存已清（恢复官方 0.5 mask）。以下为当初的修复记录，若将来还想启用可据此重做：
   ⚠ 相关参数：重绘区上边界 `MUSETALK_UPPER_BOUNDARY_RATIO=0.58`（官方默认 0.5，见 `_restart_engine.sh`）——0.5 时上唇被整体重绘得「淡而糊」、说话时显薄（用户反馈 2026-10-12）；调大后上唇保留原片的饱满唇形。**改这个参数后必须清 `data/cache/precompute`**（mask 变了但预处理缓存 key 不含该参数，不清会读到旧 mask、不生效）。
