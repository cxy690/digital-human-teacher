# 真人视频数字人教师 · 部署与切换指南

> 目标：把 AI 教师从「照片木偶」（静态照片 + 局部形变）升级为「真人视频数字人」——
> 老师像真人直播一样说话，口型、眨眼、微表情由渲染引擎生成。

> ⚠️ **更新说明（与当前代码对齐）**：项目已演进为**多老师**体系 —— 每位老师 = 一个学科，
> 素材放在 `data/teachers/<学科key>/`（`talk.mp4` + `voice_ref.wav` + `teacher.json`），
> 引擎按 `teacher_id` **懒加载**底片（不再使用 `data/raw/老师*s.mp4`、`data/ai_teacher/底片.mp4`）。
> 数字人引擎脚本为 `scripts/avatar_engine_musetalk_v15.py`（新版 API、绕开 mmcv）。
> 云端部署见 [`算力云部署.md`](算力云部署.md)。下文保留历史细节，**路径以 `data/teachers/<key>/` 为准**。

## 一之二、引擎选型（1对1 实时口型）

本项目数字人为 **1对1 实时答疑** 服务，实时口型引擎可通过 `.env` 切换、代码零改动（适配器见 `models/avatar.py`）：

| 用途 | 选型 | 引擎脚本 | 契约 | `.env` 开关 |
| --- | --- | --- | --- | --- |
| **实时口型（首选）** | **MuseTalk 1.5**（MIT，V100 级 30fps+） | `scripts/avatar_engine_musetalk_v15.py`（:8012） | `POST /render` | `AVATAR_BACKEND=musetalk` |
| 实时口型（备选） | LatentSync（Apache-2.0，中文唇形强，显存≈6.5GB） | 同上（:8012） | `POST /render` | `AVATAR_BACKEND=latentsync` |
| 兼容兜底 | Wav2Lip（口型精度低于 MuseTalk）；照片木偶（无引擎时） | `scripts/avatar_engine_wav2lip.py`（:8011） | `POST /render` | `AVATAR_BACKEND=http` / `mock` |

> **为什么不用 Wav2Lip 作首选**：MuseTalk 1.5 输出 256×256 且实时性更好；Wav2Lip 仅重建 96×96 嘴部、牙齿糊，保留为已接通的兼容兜底。

**横向扩容（文档 3.1 工程提示）**：消费级显卡画质与延迟不可兼得，服务端建议 **L40S / A10 起步**；
并发学生数增多时多起几个引擎实例（`ENGINE_HOST=0.0.0.0` + 不同 `ENGINE_PORT`），前面挂负载均衡，
把 `.env` 的 `AVATAR_API_BASE` 指向 LB 地址即可，业务代码无需改动。

## 二、切换到真人视频数字人需要什么

### 硬件（自部署路线）

| 项目 | 最低 | 推荐 |
| --- | --- | --- |
| GPU | NVIDIA 8GB 显存（RTX 3060 / V100） | RTX 4090 / A10，16GB+ |
| 内存 | 16GB | 32GB |
| 系统 | Ubuntu 20.04+ / Windows + WSL2 | Ubuntu 22.04 |
| 其他 | CUDA 11.8+、ffmpeg、Python 3.10 | — |

> 单卡大约支撑 **2~4 路并发**实时渲染。并发更高时，云端 API（按分钟计费）通常更划算。

### 形象素材（二选一）

1. **AI 生成形象 + 一段素体视频**：用与形象图同一个人物生成 2~3 分钟正面讲解视频（绿幕/纯色背景，说话时嘴部动作清晰），作为驱动底版；
2. **签约模特录制**：效果最接近真人，但必须签署**肖像权授权书**（见第六节合规）。

### 形象数据集规格（对齐立项方案 4.1，克隆老师 ≤ 3 天上线的基础）

上面的「2~3 分钟素体视频」只够跑通链路；要**克隆一位可商用的老师形象**，按文档 4.1 采集：

| 项 | 规格 | 用途 |
| --- | --- | --- |
| 授课视频 | **2-4 小时**高清正面录像，1080p/4K，固定机位，均匀布光，绿幕/纯色背景，25/30fps | 驱动底片 / 微调 |
| 口型覆盖 | 语料覆盖**中文全部音节** | 保证唇形驱动无盲区 |
| 情绪覆盖 | 讲解/提问/鼓励/严肃等 **4-6 种**教学情绪；头部转动 **±30°**；含上半身自然手势 | 表情/姿态自然度 |

### 素体视频拍摄清单（拍之前务必对照）

视频驱动类引擎（MuseTalk / Wav2Lip / metahuman-stream）是**在素体视频上重建嘴部区域**，
所以底片质量直接决定成品质量。不合格的素材会让引擎「嘴歪、牙齿糊、脸部抖动」。

| 项目 | 要求 | 不合格的后果 |
| --- | --- | --- |
| 时长 | 2~3 分钟（训练型平台 5~10 分钟） | 太短导致模型泛化差 |
| 机位 | 固定三脚架、正面平视、锁定焦距 | 变焦/晃动会让脸型漂移 |
| 构图 | 正面半身，头顶留白约 5%，头部居中 | 侧脸角度 >15° 会重建失败 |
| 背景 | 纯色或绿幕，无杂物、无其他人 | 背景干扰影响抠像与追踪 |
| 光线 | 两侧补光、均匀面部、无硬阴影 | 阴影跳动会让脸部忽明忽暗 |
| 帧率/分辨率 | 25~30fps、1080p 以上 | 低帧率口型会有卡顿感 |
| 嘴部 | 口型清晰、语速平稳、**闭嘴时嘴唇自然闭合** | 全程露齿微笑会让嘴型重建异常 |
| 眼睛 | 刘海不遮眼、**不戴反光眼镜**、保持自然眨眼 | 眼镜反光会让眼部区域崩坏 |
| 动作 | 小幅自然点头/轻微呼吸起伏，不要大范围移动 | 出画或大幅移动会丢帧 |
| 音轨 | 可以正常说话录音（**原音轨最终会被丢弃**，驱动用 TTS 音频） | — |
| 道具 | 手不要托脸、不要在嘴边出现笔等遮挡物 | 遮挡区域无法重建 |

> 拍摄时的"说话内容"不重要，重要的是**口型动作丰富、表情自然**——
> 可以念一段课文或绕口令，覆盖 a/o/e/i/u 各种口型。

**不想录视频？三条替代路径：**

1. **照片驱动**（你现在这档的升级版）：只用一张照片，LivePortrait / EchoMimic / Hallo 类模型可生成眨眼与表情，省事但口型精度与稳定性低于视频驱动；
2. **云端"训练专属形象"**：上传照片或视频到 HeyGen / D-ID / 腾讯智影 / 硅基智能等平台，训练几分钟~几小时，之后按 API 调用，无需自己维护 GPU；
3. **AI 生成"同一人物"的讲解视频**当作素体素材：用图生视频工具基于现有形象图生成正面讲解片段，再拿去驱动——
   好处是形象完全可控、无肖像权风险；代价是需要人工筛选合格片段。

## 三、方案 A：metahuman-stream 自部署（推荐起步）

该项目把 MuseTalk / Wav2Lip / ER-NeRF 等封装成实时流式服务，自带 WebRTC 推流，与本项目最契合。

```bash
# 1. 拉取代码（示例，具体以项目 README 为准）
git clone https://github.com/lipku/metahuman-stream.git
cd metahuman-stream

# 2. 安装依赖（建议独立 conda/venv 环境，Python 3.10）
pip install -r requirements.txt

# 3. 准备形象素材：把素体视频放到 data/ 下，例如 data/avatars/teacher.mp4

# 4. 启动渲染服务（示例端口 8011）
python app.py --transport webrtc --model musetalk --avatar_id teacher --listenport 8011
```

启动后先确认服务自身可用：

```bash
curl http://127.0.0.1:8011/health
```

### 对接本项目

metahuman-stream 的原生接口形态与本项目约定不同（它走 WebRTC 房间），
因此用仓库自带的**适配器**做协议转换：

```bash
# 适配器把 POST /render 转发到上游引擎
AVATAR_UPSTREAM=http://127.0.0.1:8011/render python scripts/avatar_adapter.py
```

如果上游返回字段不同（`video` / `video_base64` / `stream_url` 等），
适配器里的 `_normalize()` 已做归一化，按实际情况补一行映射即可。

## 四、方案 B：直接对接符合契约的服务

本项目对引擎的最小契约只有一条：

```
请求  POST {AVATAR_API_BASE}/render   {"audio": "<base64 音频>", "text": "这一句的话术"}
响应  {"video": "<base64 mp4>", "mime": "video/mp4"}   或   {"stream_url": "wss://..."}
```

> **重要：返回的视频必须自带音轨**。视频模式下前端只播放视频、不再单独播 TTS 音频，
> 音轨缺失会导致「学生看到老师说话但听不到声音」。
> 若你的引擎只能返回无声视频，在 `.env` 里设 `AVATAR_VIDEO_HAS_AUDIO=false`，
> 系统会额外下发 `ai_audio` 事件补上声音（口型与语音的同步精度会略降）。

* 若你的引擎（自研的、MuseTalk 二次封装的）**已经符合**这个契约，
  直接把 `AVATAR_API_BASE` 指过去即可，**适配器都不需要**；
* 若不符合（绝大多数情况），跑 `scripts/avatar_adapter.py` 做转换。

### 没有 GPU 也能先验证链路

用一段示例 mp4 走通全链路（验证「AI 说话 → `ai_avatar` 事件 → 前端播放视频」是否通畅）。
仓库已内置示例素材 `data/teachers/<学科key>/talk.mp4`（正面半身、**可无音轨**）：

```bash
# 终端 1：启动适配器，用示例视频充当渲染结果
AVATAR_STUB_VIDEO=data/teachers/chinese/talk.mp4 python scripts/avatar_adapter.py

# .env 里打开视频链路（示例视频无音轨，故关掉 HAS_AUDIO；无 TTS Key 时需允许静音调用）
#   AVATAR_BACKEND=http
#   AVATAR_API_BASE=http://127.0.0.1:8010
#   AVATAR_VIDEO_HAS_AUDIO=false
#   AVATAR_ALLOW_SILENT_AUDIO=true
```

重启服务后打开学生端，AI 每次说话都会播放这段视频——用来确认管线通了即可，
真实效果要等接入带音轨的真引擎。

## 五、切换开关（改 .env 即可，代码零改动）

```ini
# 关闭视频数字人，回到照片木偶（默认）
AVATAR_BACKEND=mock

# ── 实时口型引擎（首选 MuseTalk 1.5）──
AVATAR_BACKEND=musetalk                     # musetalk / latentsync / http（通用契约或 Wav2Lip）/ mock
AVATAR_API_BASE=http://127.0.0.1:8012       # MuseTalk 引擎地址（latentsync 同理，指向其服务）
AVATAR_API_KEY=                             # 需要鉴权时填
AVATAR_TIMEOUT_SECONDS=60
AVATAR_VIDEO_HAS_AUDIO=true                 # 引擎返回视频自带音轨（真实引擎保持 true）
AVATAR_ALLOW_SILENT_AUDIO=false             # 无 TTS 音频时是否仍调渲染服务（仅示例视频空跑用）
AVATAR_SOURCE_IMAGE=                        # 老师肖像/底片图（http 渲染服务驱动用）
```

> 切换后**必须重启主服务**（`get_avatar()` 带 lru_cache）。

### 启动引擎（独立环境，需 GPU）

```powershell
# 实时口型：MuseTalk 1.5（独立环境，需先克隆 MuseTalk 仓库 + 下载权重）
$env:MUSETALK_DIR="D:\MuseTalk"; python scripts\avatar_engine_musetalk_v15.py  # :8012 POST /render

# 主服务（tea 环境）
python -m server.app
```

> 引擎脚本与旧 Wav2Lip 引擎同构：通过 `sys.path` 引入对应仓库的推理工具，
> 与仓库版本耦合的入口已在脚本内标注（MuseTalk 的 `load_all_model`），按实际版本对齐一处即可。

改完重启服务：`python server.app` / `python -m server.app` 均可。

### 自测清单

1. `curl http://127.0.0.1:8010/health` → `{"status":"ok","mode":"upstream"|"stub"}`
2. 打开学生端（`.env` 里 `PORT=8001` → http://127.0.0.1:8001），点「开始对话」
3. 浏览器 F12 → 网络 → WS → 消息里应看到 `{"type":"ai_avatar", ...}`
4. 教师形象区播放视频；**播放结束后自动恢复照片木偶待机**
5. 故意把 `AVATAR_API_BASE` 改错再试一次 → 应自动回退到 `ai_audio + 口型`，**语音不会中断**

## 六、性能与延迟

管线是**逐句流水线**：LLM 出第一句 → TTS 合成 → 数字人渲染 → 推流，
下一句与上一句的渲染重叠，端到端首帧延迟通常可压到 **1~2 秒**。

| 环节 | 典型耗时 | 优化手段 |
| --- | --- | --- |
| LLM 首句 | 300~800ms | 流式输出、限制首句长度 |
| TTS 单句 | 200~500ms | 流式 ASR/TTS、就近部署 |
| 数字人渲染 | 300ms~1.5s/句 | GPU 加速、降低分辨率、句长切分更细 |
| 传输 | 50~200ms | **建议从 base64 事件升级为 WebRTC**（见下） |

> 当前实现通过 WebSocket 下发 base64 视频，句子短时体验可接受；
> 长讲解或多路并发建议升级为 WebRTC 推流（`RTC_*` 配置项已预留）。

## 七、合规红线（教育场景必须处理）

1. **肖像权**：使用真人影像（含 AI 生成的真人风格面孔）需取得书面授权；
   签约模特请签《肖像使用授权书》，明确使用范围与期限。
2. **AI 身份标识**：界面须明示「AI 教师」，不得让未成年人误以为是真人授课。
3. **未成年人数据**：学生的画面在**端侧处理**，不上传原始人脸图像；
   家长授权与隐私政策要齐备。
4. **内容安全**：教师话术需过内容审核，避免错误知识与不当表达。

## 八、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 一直是照片木偶 | `AVATAR_BACKEND` 仍是 `mock`，或引擎不可达 | 检查 `.env` 与 `/health` |
| 播放一下就没了 | `AVATAR_STUB_VIDEO` 路径不存在，返回 503 | 检查适配器日志 |

| 换形象后口型对不上 | 新照片五官位置变了 | 用 `scripts/prepare_avatar.py <新图>` 生成锚点预览图，按预览微调 CSS 里的锚点百分比 |
| 页面没更新 | 浏览器缓存 | Ctrl+F5 强制刷新 |

## 九、换形象图（照片木偶）的正确姿势

```bash
python scripts/prepare_avatar.py <你的新照片> --save clients/student_tablet/ai_teacher2.png
```

脚本会：
1. 裁掉底部水印并保证 **3:4** 比例；
2. 生成 `*_anchors.png` 校准预览图（用红圈标出嘴部/双眼锚点当前位置）。

打开预览图检查红圈是否套住五官，偏差则微调 `index.html` 中三处锚点百分比：

* `#mouth-layer` → `radial-gradient(... at 50% 48.8%)` 与 `transform-origin`
* `#eye-layer-l` → `41.6% 33.4%`
* `#eye-layer-r` → `58.4% 33.4%`

> 注意：照片必须与锚点坐标匹配 —— 换图后务必走一遍这个校准流程，否则会出现「嘴在对的地方、眼睛在额头」这类问题。

## 十、Wav2Lip 真唇形同步（兼容兜底，本机自部署，已接通）

> 定位：文档 3.1 首选为 **MuseTalk 1.5**（见一之二节与 `scripts/avatar_engine_musetalk_v15.py`）。
> Wav2Lip 口型精度较低（仅重建 96×96 嘴部），作为**已接通的兼容兜底**保留；
> 新部署优先用 MuseTalk（`AVATAR_BACKEND=musetalk`）。

已用**独立环境** `wav2lip` 部署 Wav2Lip 引擎，服务文件 `scripts/avatar_engine_wav2lip.py`，
监听 `127.0.0.1:8011`，符合本项目的 `POST /render` 契约（返回**自带音轨**的 mp4），
用底片做基底逐帧重建嘴部区域，实现口型与语音**逐字同步**。

### 启动（两个进程）

```powershell
# 1) 渲染引擎（独立 wav2lip 环境，需 NVIDIA GPU）
$env:WAV2LIP_DIR="D:\wav2lip"; D:\An\envs\wav2lip\python.exe scripts\avatar_engine_wav2lip.py

# 2) 主服务（tea 环境）
python server.app
```

`.env` 关键项：`AVATAR_BACKEND=http`、`AVATAR_API_BASE=http://127.0.0.1:8011`、`AVATAR_VIDEO_HAS_AUDIO=true`。
改完**必须重启主服务**（`get_avatar()` 带 lru_cache）。

### 一次性准备（依赖 + 代码 + 权重）

```powershell
conda create -n wav2lip python=3.10 -y
# RTX 50 系(Blackwell)必须用 cu128 版 PyTorch
d:\An\envs\wav2lip\python.exe -m pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu128
d:\An\envs\wav2lip\python.exe -m pip install opencv-python librosa soundfile scipy tqdm numba imageio imageio-ffmpeg fastapi uvicorn httpx
# 代码（GitHub 直连不通时用 ghproxy 代理）
git clone --depth 1 https://ghproxy.net/https://github.com/Rudrabha/Wav2Lip.git D:\wav2lip
# 权重：checkpoints/wav2lip_gan.pth 与 face_detection/detection/sfd/s3fd.pth
#       可从 HuggingFace 镜像获取：https://hf-mirror.com/camenduru/Wav2Lip
```

引擎环境变量：`WAV2LIP_DIR`(默认 `D:\wav2lip`)、`WAV2LIP_CHECKPOINT`、`AVATAR_FACE_VIDEO`(底片，默认 `data/teachers/<学科key>/talk.mp4`)、
`WAV2LIP_RESIZE`(默认 2，降分辨率加速)、`WAV2LIP_BATCH`(默认 64)、`WAV2LIP_DET_DEVICE`(人脸检测设备，默认 `cpu`)、`ENGINE_PORT`(默认 8011)。

学生端形象：待机（含学生提问时）显示静态微笑图 `clients/student_tablet/ai_teacher_smile.png`；
AI 讲解时播放上述引擎逐句渲染的对口型视频（含底片里的手部动作），播完自动回到微笑待机。

> 注意：底片帧数不足音频时长时会**循环取帧**；底片若有水印会被一并带出。
> 实测：RTX 5070 Laptop(8GB)、一句约 7 秒语音约十余秒出片，端到端可用。

## 十一、团队共享引擎 + 无引擎兜底

学生端的数字人视频由**本地 Wav2Lip 引擎**生成。组员只拿到项目文件夹时没有该引擎（环境/代码/权重/GPU 均不在项目内），
教师会退化为“静态形象 + 轻量口型兜底”。要全组都有真·对口型视频，在**一台有 GPU 的机器**上对外提供引擎即可。

### A. 一台机器供全组用（推荐，组员无需 GPU）

1) 引擎机启动（对外监听）：
```powershell
$env:WAV2LIP_DIR="D:\wav2lip"; $env:ENGINE_HOST="0.0.0.0"; D:\An\envs\wav2lip\python.exe scripts\avatar_engine_wav2lip.py
# 引擎机需放行防火墙 8011 端口
```
2) 组员机器 `.env`：
```ini
AVATAR_BACKEND=http
AVATAR_API_BASE=http://<引擎机IP>:8011
```
   改完**重启主服务**。
3) 验证：组员浏览器访问 `http://<引擎机IP>:8011/health` 应返回 `{"status":"ok",...}`。

> 组员**不需要** torch / Wav2Lip 权重 / GPU，只需主项目环境（conda `tea` + requirements）。
> 前提：组员与引擎机在同一局域网（能访问其 `IP:8011`）；异地需端口映射/VPN 或把引擎部署到公网服务器。

引擎新增环境变量：`ENGINE_HOST`(默认 `127.0.0.1`；设 `0.0.0.0` 可被其他机器访问)。

### C. 无引擎时的轻量兜底（已内置，默认生效）

若引擎不可达，主服务自动回退到 `ai_audio`；前端用 **TTS 音频能量驱动待机图嘴部开合**（略机械但“会动”），
不会出现“教师完全静止”，也不会发出第二种声音。有视频时以真视频为准，两者互不影响。
