Agent 调度关系与协作

谁触发谁 · 谁让位给谁 · 出事退给谁

① 事件入口 core/loop.py · SessionLoop._dispatch()

  • vad 逐帧麦控 · voice ASR→回合 · text 文字提问
  • image 拍照讲题 · interrupt 只作废播报
  • idle 空闲问候 · course_start/phase/quiz_request
  • courseware / slide_goto / slide_step / slide_play / slide_stop
  • slide_ready 就地处理：主循环正卡在 _await_page_played 等它，入队会永远轮不到
➜

② 总控 Supervisor（唯一有状态 Agent）

  • 独占 SessionState：唯一共享黑板（白板指令 / 历史 / 麦控 / 课件页序 / scratch）
  • 持有执行者：StudentAgent · TeacherAgent · LecturerAgent
  • 持有决策与支撑：IntentAnalyzer · Validator · QuestionParser · Guardrail · Retriever
  • 装配方：core/harness.py · core/loop.py · a2a/executor.py（单向依赖，无循环 import）
➜

③ 回合决策树 handle_turn → _handle_turn_builtin

  • 待答追问优先 → _turn_answer_check()：直接判题，不重新路由
  • 否则 IntentAnalyzer.analyze_async() → IntentDecision
  • 非控制诉求 ≥2 → _turn_multi_intent() 逐条独立走完整链路
  • 混装 control / CONTROL → _handle_control() 当场办、不出声
  • CHITCHAT → _turn_chitchat() 不进答疑链路
  • 其余 → _turn_teach() → _run_answer_pipeline()
  • 两套编排同一份判定：内建 / core/turn_graph.py 的 route 节点
➜

④ 执行者 agents/ 三个角色

  • TeacherAgent（teacher）：answer / answer_image / evaluate_answer / explain_slide（回退实现）
  • LecturerAgent（lecturer）：explain_slide → points + annotations，不写正文板书
  • StudentAgent（student）：麦控状态机、摄像头/麦克风、构造回合
  • 产物统一出口：board_ops 白板 + ai_speech 文本 + TTS/数字人

答疑通路 Supervisor._turn_teach

handle_turn→ 待答追问优先→ IntentAnalyzer→ _turn_teach→ _run_answer_pipeline→ TeacherAgent.answer→ Validator + Guardrail→ 白板 + 播报
TaskGraph 子图：retrieve → generate → validate → solve图片题走 answer_image

讲课通路 Supervisor._play_slides

handle_courseware→ _play_slides()→ 逐页 _explain_slide(i)→ LecturerAgent.explain_slide→ annotations 页面标注→ 换页 + 播报→ 等 slide_ready
入口：slide_goto / slide_step / slide_play每页等前端播完再翻下一张

麦控通路 StudentAgent 状态机

vad(has_voice) 逐帧→ 麦控状态机→ 倾听 / 静默触发→ 插话让位→ on_voice(audio)→ ASR→ StudentTurn → handle_turn
学生开口时 AI 静默不抢人声学生静默后自动触发答疑

协作三机制 agents/protocol.py

  • 共享上下文：SessionState 唯一黑板，所有 agent 读写同一实例、不互相拷贝
  • 消息传递：agent 之间零直接调用，只把交互记成 AgentMessage 投 AgentBus
  • 事件触发：扇出客户端事件 agent_message + 环形缓冲 80 条
  • 只记转交与异常：request · handoff · fallback · error（逐回合记会刷满缓冲）

抢占与打断

  • 学生新输入入队瞬间即 _barge_in()：speech_epoch += 1 + 下发 avatar_interrupt，旧播报在下一个句边界中止（分发时再调一次，双保险）
  • 讲课中学生提问 = 让位：_record_lecture_handoff() 记一条 handoff（lecturer → teacher）
  • 去重键 = speech_epoch（多意图逐条作答每轮只记一次）
  • 判定依据是「有没有打开课件」，不是 auto_playing

失败与回退

  • 讲课 LLM 失败 / 非法 JSON → LecturerAgent 降级「本页要点口播」，绝不哑巴翻页
  • 讲课契约漂移（返回了答疑的 steps）→ _heal_points() 自愈出本页要点
  • 讲课链路整体异常 → 回退 TeacherAgent.explain_slide → 仍失败记 error + 兜底话术（不因一页打断整节课）
  • 意图小模型超时 → 保留规则结果；RAG 失败 → 静默忽略退化为纯 LLM
  • 白板指令越界 → 只丢该条，不整块清屏

职责边界 总控刻意不做什么

  • 不生成话术：文本全部由 TeacherAgent / LecturerAgent 产出
  • 不判学科：越界与内容安全交给 core/guardrail.py
  • 不解析题目：OCR 与结构化在 document_parsing/
  • 不占模型额度做判定：学科护栏、白板校验、验算都是本地逻辑
  • 不互相调用 agent：协作只靠共享上下文 + 总线记录 + 上下文注入

学科老师 Skill 加载链路

一份 SKILL.md → 两个适配器 → 注入提示词

① 事实源 .agents/skills/<学科key>/SKILL.md

  • 11 科各一份，运行期现读（改 md 即生效，无需改 Python）
  • frontmatter：name subject_key skill_id class_name display_name persona style_persona tone depth speech_rate teaching_style greeting_default catchphrases do dont
  • 正文小节：说话风格 · 讲课方式 · 人格与教学 · 九项行为 · 进场问候
  • references/ 流派设计稿：人读，不注入提示词
➜

② 解析 config/teacher_skills/md.py

  • parse_skill_md() → SkillDoc（frontmatter + ## 小节 字典）
  • 剥掉 > 注解块与 HTML 注释 —— 注解给人读，不进提示词
  • 必填字段校验：缺一项即视为不完整 → 调用方回退默认 persona，绝不注入半份人格
  • 按 mtime 失效缓存：线上改一份 md，下一次调用即生效、不需要重启
  • 单份 md 解析失败 → 只告警跳过，不拖垮整节课
➜

③ 两个适配器 同一份 md，两个消费者

  • 风格层 load_skill(key) → TeacherSkill：说话风格 / 讲课方式 / 深度 / 语速 / 口头禅
  • 人格层 build_skill_class(doc) → MarkdownTeacherSkill 子类 ×11（MathTeacherSkill …），把 skill_id/subject_id 写成类属性
  • → TeacherSkillRegistry（SKILLS / SKILL_ORDER / SKILL_CLASSES）
  • 查找：get_for_subject() / get_for_session()；找不到返回 None，绝不跨学科顶替（防串台）

④ 装配共享层 agents/shared/teaching_layers.py · build_profile_layers(session)

  • 1 讲课风格 STYLE_GUIDE：plain（大白话）/ normal（按学段）/ academic（规范术语），取自 md 的 teaching_style
  • 2 老师人格 profile.persona_text()：按 session.scratch.teacher 选中变体；变体复用本学科 md 的教学法，只替换「说话风格」（_base_skill() ← skill_key）
  • 3 平台底线 + 学科人格：GLOBAL_TEACHER_RULES + p_skill.build_system_prompt()；subject_id 与当前学科不符即丢弃（防串台）
  • 4 经验层 build_experience_prompt(profile.key)：self-update 沉淀，只读，人格本体永远由人维护
  • 答疑与讲课共用这一层 → 保证两条链路是「同一位老师」
➜

⑤ 组装 messages build_messages(session, contract=…)

身份基座→ 任务契约→ 学科约束→ 作业提示→ 任务附加→ 共享人格层→ 任务覆盖层→ 会话历史→ 本轮输入
层序越靠后影响力越强 答疑契约 ANSWER_CONTRACT 讲课契约 LECTURE_CONTRACT LECTURE_BOARD_OVERRIDE 覆盖人格里的「白板组织」
➜

⑥ 落点 Qwen3 → 白板 / 语音 / 数字人

  • 答疑输出：speech title steps knowledge_points pitfalls answer followup
  • 讲课输出：speech points annotations
  • → board_ops 白板指令 + CosyVoice 语音 + 数字人口型
  • → 学生端播放；追问卡片 ai_ask 等待作答后走 _turn_answer_check
